# Requirements: Linking Lab Pre-Interview Tasks

**Defined:** 2026-10-18
**Core Value:** Show sound, transparent, source-critical problem solving on realistic HisPeR data within a ~3.5-hour budget — clear assumptions, decisions and conclusions matter more than completeness or polish.

## v1 Requirements

Requirements for the hand-in (deadline 23:59 2026-10-18). Each maps to a roadmap phase.

### Setup

- [ ] **SETUP-01**: Environment is reproducible via `uv sync` (pinned `pyproject.toml` + `uv.lock`)
- [ ] **SETUP-02**: A fetch/convert script extracts only the 5 `census_{1801,1850,1860,1880,1901}__v1__cl.csv` files and the Release 2 Guide from the Digidata zip and writes parquet
- [ ] **SETUP-03**: `MF_census_1850_1846_cl.xlsx` is converted to parquet by script; raw data and named record-level data never enter git

### EDA

- [ ] **EDA-01**: Task 1 rendered notebook shows `handicaps` per year (1801/1850/1860/1880/1901): missingness, cardinality, frequency/coverage curve, examples of messy values
- [ ] **EDA-02**: Task 1 notebook shows a column overview (type, % missing, cardinality, examples) describing what the data shows, without asserting official definitions
- [ ] **EDA-03**: Task 2 rendered notebook shows the DWI column overview plus 1846→1850 stability of the free/enslaved flag, owner fields, surnames, and age noise
- [ ] **EDA-04**: EDA produces the facts needed for pending decisions: Task 1 approach, blocking window width, LLM-for-categories, embedding scope

### Task 1 — Harmonization

- [ ] **HARM-01**: Raw `handicaps` values are spelling-normalised automatically (case, punctuation, whitespace, variant spellings)
- [ ] **HARM-02**: File A `handicaps_mapping.parquet` has one row per distinct normalised value with per-year frequency, proposed standard value and confidence
- [ ] **HARM-03**: File A carries a *suggested* category per value, clearly marked as suggestion for historians (method decided after EDA)
- [ ] **HARM-04**: File B `handicaps_review.parquet` (+ CSV export) is the review subset for Asbjørn — selected by impact (definition written by the user), sized from the brief's 100–120 records/hour, with empty `decision` and `comment` columns
- [ ] **HARM-05**: Task 1 README gives the overview — EDA findings, assumptions, decisions, conclusions, next steps
- [ ] **HARM-06**: Values that differ in wording rather than spelling (e.g. "blind" vs "svagsynet"): scope confirmed after the EDA is zero (Phase 2 D-07, D-18). No embedding grouping is built in this iteration; the Task 1 README documents embedding-similarity grouping (nearest frequent anchor, cosine similarity as confidence) as a next step, with the modern-meaning-bias caveat.

### Task 2 — Linking

- [ ] **LINK-01**: Candidate pairs are generated by blocking on sex + birth-year window (width set from EDA)
- [ ] **LINK-02**: Comparison features per pair: given-name similarity (normalised), surname similarity (when both present), |age difference − 4|, birthplace / island / owner agreement
- [ ] **LINK-03**: Hand-rolled additive score with given-name agreement weighted by name frequency
- [ ] **LINK-04**: Household second pass raises the score for co-residents of already-linked household members
- [ ] **LINK-05**: Greedy 1:1 assignment produces `links.parquet` with `pa_id_1846`, `pa_id_1850`, `score`, `margin`, `confidence_band`
- [ ] **LINK-06**: Plausibility evaluation: age-difference distribution, link rates by sex/island/free-enslaved status, sample pairs per confidence band
- [ ] **LINK-07**: Task 2 README gives the overview — method, assumptions, decisions, results, limitations, next steps

### Hand-in

- [ ] **DOC-01**: Root README: how to run, what's where, links to both task READMEs, one sentence on time spent, one line on AI use pointing to `.planning/`
- [ ] **DOC-02**: `QUESTIONS.md` — written by the user after discussing the questions
- [ ] **DOC-03**: Cover email draft (link/zip, time spent, entry points)

## Out of Scope

| Feature | Reason |
|---------|--------|
| Phonetic keys (Soundex/Metaphone) | Load-bearing with unclear usefulness; abbreviations and mixed-language names break them |
| Snakefile in the hand-in | No real need for 4–5 short scripts; time is scarce |
| Excel output | Parquet everywhere; CSV export only where historians need it |
| Standalone column dictionary file | Shown in EDA notebook only; official column meanings unknown |
| Tests, CI, linter config, package layout | Ceremony for a hand-in this size |
| Full standardisation of `handicaps` | Brief asks for the first iteration only |
| Time-log table | One sentence in the README suffices |
| Splink in v1 | Hand-rolled approach shows own design |
